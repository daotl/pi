- Finalization checks cancellation before its first asynchronous operation and immediately before checkpoint append. Summary authentication receives the same abort signal. Prepublication cancellation emits no checkpoint and retains completed built-in usage.
- A failed checkpoint append likewise retains the completed charge as a context-invisible, physically attributed usage entry. The original append/cancellation failure is preserved.
- If that receipt cannot be appended, a session-owned pending queue retains a deep copy. Accepted prompt/continuation/manual compaction and request preparation flush it before dispatch; automatic compaction also flushes before generating work. Storage failure prevents another paid request rather than silently losing a charge.
- Shift the pending receipt only after its append succeeds, before public entry notification. A listener error after persistence cannot cause another charge. A committed checkpoint's later listener or final context-count error likewise does not manufacture a receipt.

No S9 upload permission, adapter output clamp, file attribution or exact-count identity change.

Runtime new/resume/fork/import/dispose uses it before invalidation; raw `AgentSession.dispose()` keeps its nonthrowing cleanup contract. Runtime dispose now awaits abort/settlement first. No receipt notification can start an outgoing run during this storage drain.
