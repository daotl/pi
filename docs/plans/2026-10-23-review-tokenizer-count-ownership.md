## Implementation and boundaries

The stored count now owns its checkpoint ID, context-edit ID, selected leaf and selected model object. Ownership is captured before awaited full-context policy/counting work. getContextUsage accepts it only when all owners match the current canonical context and no applicable post-compaction provider usage exists. Projected omitted/error/aborted response records do not make raw historical usage current. Selected-model identity is intentional: an auth baseURL overlay can produce a different request model object without changing the selection; replacing/switching the selection must invalidate the count.

Only an actual successful count populates the slot. Compaction still returns estimatedTokensAfter and uses local estimates for preparation, but denied/unavailable/transient final counting leaves footer tokens/percent unknown. A summary-budget change clears the existing slot; an additional publication guard rejects an in-flight count started under another budget, preventing late assignment from resurrecting an invalidated value.

Footer cache identity includes the effective summaryBlockMaxTokens value. Its existing invalidate() remains a no-op because InteractiveMode invokes it on every event; turning that into a full statistics reset would restore per-stream-event history scans. A separate invalidateSessionStats() clears the statistics only after successful compaction_end, followed by the existing render request. Unchanged frames retain session/leaf/count/model/budget caching. Fake contracts were updated rather than adding production fallbacks.

The Set used to recognize projected assistant source IDs is dynamic runtime membership, built from current canonical projection and queried across post-checkpoint entries; it is not a static string-keyed lookup table. No broad identity/version abstraction or new persistence schema.
