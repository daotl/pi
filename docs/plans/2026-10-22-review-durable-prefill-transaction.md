## Adaptation and invariants

- Capture changes only the live/request projection. The original prefix, ordered suffix, selected leaf and file bytes remain unchanged while the provider is held.
- `replaceAssistantContinuation` preallocates clone IDs, replaces the contribution at its canonical position, retains the entire suffix, removes edits targeting the consumed prefix, and remaps branch-local references. The actual response gets a fresh charge; replayed suffix charges retain transitive identity.
- `restoreAssistantPrefill` stages the saved prefix and ordered replayable recovery suffix together. Conversation/tool attempts remain historical; system/custom/state/summary/usage/context-edit records remain available. Forward references and retained compaction boundaries are remapped; invalid boundaries fall back to the restored prefix.
- Both transactions copy supersession metadata rather than mutate held historical objects. The file rewrite must succeed before entries, maps, labels, leaf and flushed state publish. Write/fsync/close/rename failures leave bytes, live indexes, tree, projection and held source objects unchanged. Deletion/tool-call deletion metadata is preserved.
- Raw terminal echo validation occurs before mutable hooks. Hooks may normalize a verified answer before storage. A complete echoed aborted response can replace the prefix; truncated abort/error restores it. Existing terminal publication barrier still prevents tools from executing before validation/persistence completes.
- Public `message_end` listeners retain their existing pre-persistence ordering. A listener or replacement write/rename failure keeps one content-free completed error receipt with physical API/provider/model, response model, diagnostics and usage. This is not a claim that every public notification follows durable storage.
- Failed restoration releases run ownership but retains the saved prefix, restore point, suffix and captured branch. The next accepted prompt/continuation/request preparation retries restoration before provider dispatch. Successful accepted tree navigation supersedes abandoned recovery; cancelled navigation does not.
- Retry re-arm uses the actual canonical candidate/source after recovery. Recovery input can take precedence over the earlier prefix. Approved retry/queue ordering, physical-origin eligibility and the existing completed-stop candidate gate remain unchanged.
- Public `continue(prefill?)` now accepts `AssistantMessage`, matching the real prefix contract. TypeScript references found 26 consumers; current production callers omit the argument. No compatibility shim or additional state protocol.
