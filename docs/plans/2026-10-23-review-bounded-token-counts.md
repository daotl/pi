## Adaptation and invariants

- TokenCounter gains an optional AbortSignal. Both current raw/projected loops issue at most four independent counts per batch, consume results newest-first, handle every rejection immediately, stop before another batch once cutoff is known, and abort only their batch in finally. A consumed failure propagates; an older discarded failure cannot reject the selected tail.
- Keep current raw/projected cut-point, tool atomicity, zero-budget, prompt/system exclusion, metadata and omitted recovery-tail behavior. Do not replace current algorithms wholesale with the older backup; only the counting loops change. Existing combined retention bounds remain authoritative.
- AgentSession combines parent-compaction, endpoint-capability and batch signals for each count. Cancellation reaches native HTTP and retry/policy work. Parent cancellation remains terminal to compaction; optional batch work beyond cutoff may settle as an estimate, but that slot is no longer consumed. No new public cancellation/error contract is invented for discarded speculative results.
- Share the first unknown endpoint probe. After a successful count establishes support, waiting and subsequent batch counts proceed concurrently. A definitive unavailable result stops further preparation probes for that compaction and aborts active endpoint work; a later compaction probes again. Policy denial, cancellation and transient exhaustion do not mark endpoint unavailable. Each actual attempt retains fresh auth and the previously migrated complete-history transform/converter/result/identity authorization, including late policy revocation.
- Preserve countChatTokens chat-template final counting and count ownership; no text-only final-count downgrade, new concurrency setting, dependency or scheduler abstraction.
